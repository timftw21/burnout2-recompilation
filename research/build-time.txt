Changes

The generated CPU files share a precompiled CPU header. Sequential instructions
fall through directly; genuine branches, loop checks, discontinuous successors
and fused-block exits retain explicit labels. Source scopes and overlapping
instruction streams are preserved. Generated C++ fell from 208,705,445 to
187,351,403 bytes. LLVM objects occupied 249,499,260 bytes, compared with
3,037,607,299 bytes for the saved MSVC objects.

The default preset and Build.cmd use clang-cl, Ninja and LLD. The installer
loads the x64 Visual Studio SDK environment, validates LLVM 22.1+, and refreshes
incompatible CMake metadata while retaining game files and user data. Six
compilation workers and cached parallel ThinLTO replace the slow final MSVC
optimization pass. MASM inputs remain relative, with /Fo before /Ta, so assembly
works in non-English installation folders. Audio voice initialization moved to
its constructor where the packet type is complete, preserving initialization.

Changing compilers exposed missing verified UI method registrations. Original
stores at 23580, 2B87E, 2B903 and 3D66E establish methods 22A60, BFAD0, BFD30
and BFC70. Their original bytes are checked during callback discovery. Boolean
membership checks now use ranges::contains. Both builds compile 36,149 functions
and 713,245 instructions, with 32,619 closed functions. The only per-function
report differences remove a spurious D7400 callback annotation from 2F050 and
32B60; D7400 remains compiled through verified startup roots. Existing mutable
indirect targets remain explicitly unresolved. Generated x87/MMX assembly is
identical, SHA-256:
4670BA3EDA91AF7D3C8407C922B64A3034CA3F460C928D76CB3EDE740702C5D5

Validation

Native CPU, spatial, audio/capture, effects, all twelve music tracks, storage,
replay, original-image/UI, hardware and WARP rendering, recording and hidden
window checks passed. The baseline and new boot diagnostics both reached main,
produced 53 flips and stopped at CC5C0 on the configured 1,000,000-checkpoint
limit. Three-run CPU benchmark medians improved with matching checksums:
finite helper 9.2234 -> 6.2816 ns, call chain 65.1321 -> 31.5402 ns,
fused matrix 203.388 -> 197.511 ns. Component timings do not establish game FPS.

Windows PowerShell 5.1 installations passed in normal and Japanese/accented
source/disc paths. Migration preserved actual settings and six existing saves.
Repeat Unicode setup passed with downloads blocked, refreshed the disc location,
preserved settings/saves and reused the executable in 15.970 s. Invalid disc
input failed at extraction without changing existing settings/saves. Absolute
Unicode CPU-check input passes with a UTF-8 process manifest; narrow main argv
previously lost Japanese characters before file opening. No global OS setting

The final canonical installer repeat took 17.797 s and preserved all six saves.

2026-10-11: runtime edit throughput

Removing the shader stamp's dependency on the whole shared tool avoids a needless
48-49 second HLSL compile after renderer edits. Actual generator source, headers,
verified XBE and build settings still invalidate it; tool build ordering remains.
A timestamp-only renderer rebuild took 8.553 seconds with the shader stamp
unchanged, compared with 59.292 seconds for the preceding runtime-only edit.
Configuration and resource compilation passed in the required x64 SDK environment.

2026-10-18: installer appearance and build progress

The Windows PowerShell 5.1 installer now shares the game's Segoe UI typeface,
logo, navy surfaces, orange controls and rounded panels. Its six stages follow
actual setup operations. The compile bar parses Ninja's finished/total status
from an incrementally read, shared output stream; partial lines survive polls,
and buffered lines are capped at 8 KiB. No timer estimates progress. CMake can
prune tasks after its initial graph count, so successful child exit is the final
completion signal. Errors retain partial progress and identify the current
stage; cancellation continues to stop only recorded PID/start-time matches.

The UI helper is included in cmake/package.ps1's committed-source manifest.
No additional executable, package, font or Python workflow was added.
Offscreen native rendering verified initial, compiling, ready and error layouts
without computer use. Windows PowerShell 5.1.26100.9711 checks passed split log
lines, appended output after EOF, bounded long lines, changed task totals,
successful/failed real workers and timed cancellation. The full Release build
passed, and a real incremental Ninja run passed through the same progress reader.
All owned installer/build/check workers exited. Evidence:
build/checks/display-installer-20261018.

2026-10-27: automatic Windows prerequisites

Install.cmd selects 64-bit Windows PowerShell 5.1; Build.cmd forwards to it.
After disc selection, setup reuses compatible installed tools or fetches pinned,
SHA-256-checked CMake 4.4.5, MinGit 2.56.0.4, Ninja 1.13.2 and LLVM 22.1.8.
Portable tools and verified downloads stay under build/deps/windows. The path
change is local to setup. Missing Microsoft 2026 C++ tools and SDK 26100 use
Microsoft's signed bootstrapper, or modify an existing 2026 installation.
Only the bootstrapper supports --wait. Microsoft's installer owns cancellation
and rollback; its service/MSI workers are never killed by our worker cleanup.

Actual Windows PowerShell 5.1 downloads, hashes, extraction and execution passed
with spaces, Japanese characters and an accented character in the cache path.
LLVM 23.1.4's tar.zst requires a larger decoding window than CMake/libarchive
permits; use the compatible 22.1.8 tar.xz instead. The four primary tool
executables have no Visual C++ redistributable import.
The downloaded tools built b2-tool and the full Release game, verified the
supported original XBE and passed all 52 CPU groups (26,026 instruction cases,

cache confirms all four tools came from the downloaded Unicode-path cache.
Existing Microsoft/SDK/tool reuse passed without downloads or system changes.
Private checks passed offline cache reuse, corrupt-cache replacement, hash
failure retries, cancellation, missing-program repair and cache-directory bounds.
Microsoft result handling (success, restart, cancellation, busy, failure and UAC
