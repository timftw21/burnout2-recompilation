Second optimization batch, original-byte evidence:
- 0021B080 compares (issued - requested) with (issued - completed), unsigned.
  Its completion word is *[002256C0+30], issued counter [002256C0+2C].
  It returns for completed fences, and calls 0021AFD0 when requested == issued.
- 0021AFD0 emits NV097 1D70 with that counter and advances it by two. Its
  original compiled implementation remains responsible for fence insertion.
  Native waiting formerly ignored the requested token and drained the GPU.
- Query-pool exhaustion formerly also drained all pending completions instead
  of freeing the oldest available slot. The new wait stops at its condition;
  completion polling uses DONOTFLUSH after one explicit submission flush.
- Push-buffer RAM is validated once per <=4 MiB submission. Header/payload
  checks remain per packet, and scalar words use memcpy for unaligned input.
- 0022EC59 combines listener/source dirty masks. Listener bits are low 7;
  source bits are high 16. The listener's derived orientation at +44 is kept
  when valid bit 40 is set. The native wrapper previously erased this state
  and set both masks to FFFFFFFF on every voice calculation. It now retains
  listener state and keeps source dirtiness in its original high word.
  Position, velocity, orientation and factors are compared byte-for-byte;
  new values still take effect immediately or on the original deferred commit.

Root cause: NV097 WAIT_FOR_IDLE (method 0110) was implemented as a D3D11 event
query plus a blocking CPU wait. Changing completion polling to DONOTFLUSH
preceded the increase in wait time; its driver cost was not measured separately.
This push-buffer method orders GPU work;
it does not ask the submitting CPU to wait. The bridge uses a single immediate
context, with ordered native draws/copies and owned uploads, so queued draws
must be submitted before the next method, without a CPU completion query.
CPU-visible semaphore releases, SDK requested fences, transform-result readback
and explicit CPU-idle requests retain their actual completion mechanisms.
The bounded query pool and requested-counter fixes remain in place.

Evidence: xemu's NV097 WAIT_FOR_IDLE handler updates the rendering surface and
does not invoke its CPU-side fence/wait mechanism. Microsoft specifies that
UpdateSubresource snapshots its CPU source before returning, including when
prior GPU work still uses the resource. Our dynamic vertex/index arena appends
unused space, or discards at wrap, preserving in-flight uploads. The bridge's
flush() snapshots queued guest vertices/constants into these native buffers.
All rendering and framebuffer/texture copies use the same immediate context.
These are GPU interface references, not gameplay visual references.

2026-10-10: remaining CPU work, static floating-point blocks

The fourth recording's checkpoint hints include 227C14 and 227C7B inside the
original SDK matrix routine 227BD9. Original generation called a MASM helper
for every x87 instruction and rewrote floating provenance from C++ each time.
These hints locate a candidate; their sample counts are not function timings.

The compiler now groups 4..32 consecutive ordinary x87 instructions into one
native block, without crossing a branch target, integer instruction, control
operation or CPU-flag comparison. It emits the same arithmetic opcodes and
order, using validated native pointers in place of guest addressing. Each
instruction still records its original address, opcode and memory provenance.
Code remains entirely ahead of time. No added dependency, decoding, runtime
compilation, mathematical replacement or heap allocation is involved in execution.
Diagnostic execution retains the individual original compiled instructions.
Failed memory preflight also takes that path, preserving earlier stores and
the floating state at the fault. Scheduler checkpoint locations are unchanged.

7392 blocks are emitted across the existing 36047-function native table.
A small unfused copy of the original matrix routine supports offline comparison
and timing. The checks cover 24/53/64-bit precision, four rounding modes, four
input/output alias layouts, finite values, signed zero, infinity and NaN; plus
invalid input/output boundaries. All 242 comparisons pass, including memory,
integer registers/flags, return state, floating status/tags and provenance.
