Original rendering

The game's default RenderWare device initialization at 0x000F3ED0 clears its
device globals, and the null-configuration branch at 0x000F3FB0 writes 0x11 to
0x005ACDD4. Device creation at 0x000F3FF0 reads that value at 0x000F402E and
stores it in the presentation parameters' sample-type field at 0x000F406C
(0x005A6700, parameters +16), before the call to 0x002147E0 at 0x000F4087.
These instructions were verified using the native tool's bounded analyse command,
with budgets of 90 instructions per entry; no whole-binary scan was used.
Existing captured surface-format values 0x00000128 and 0x08080124 have a zero
NV097_SET_SURFACE_FORMAT_ANTI_ALIASING field (bits 12..15): single sampling.
This establishes the original rendering used by the checked startup/capture;
it does not assert coverage of every possible Xbox video mode.
The default enhancement therefore remains antialiasing Off (original).

Anisotropic filtering already exists in the original game and was already
translated by the native renderer. Captured world draw 5 uses filter 0x02063DBB
and control 0x4003FFD0: trilinear minification, linear magnification, signed

Implementation

The Enhancements tab follows Graphics. Settings save with existing preferences
and apply on Start/Restart, preserving live game resources and prepared bindings.
Old settings files default to antialiasing=0 and anisotropy=0 (original).

Antialiasing uses one spatial FXAA pass, with Low/Medium/High quality presets.
Luminance contrast rejects flat areas; edge orientation, gradient and endpoint
search determine the perpendicular sampling offset. The quality presets use
4/8/12 endpoint-search samples, contrast thresholds and subpixel blend strengths.
RGB is filtered while original alpha is retained. It operates at the selected
internal resolution, once per original completed frame, before interpolation.
Original game targets, depth, texture feedback and reflection copies remain
unfiltered. ImGui and the FPS overlay are drawn afterward. Game HUD and text are
already composited into the source and can soften when FXAA is enabled.
No temporal history, extra game draws, runtime shader compilation or gameplay
readback is introduced. Shader bytecode is generated during the normal build.
Only enabled AA allocates its additional RGBA8 image (4 bytes per internal pixel).
Resizing/session reset recreates it; disabling AA releases it.

Anisotropic filtering offers Original, Off (1x), 2x, 4x, 8x and 16x. Original
preserves each draw's setting. Overrides select the native sampler's anisotropy
for linearly filtered textures, including render-target sampling. Point-filtered
textures retain point sampling. Original addressing, signed LOD bias and mip
limits are retained. The existing bounded sampler cache includes the override
in its key, so a strength change cannot reuse an incompatible prepared sampler.

MSAA additions (2026-10-13)

The same Antialiasing control now also offers MSAA 2x/4x/8x. Existing saved
FXAA values 1..3 are unchanged; new values 4..6 select those sample counts.
Off remains the default. Changes apply at the next session. Device capability
checks cover RGBA8/RGB565 colour, D16/D24S8 depth, multisample loads and resolves.
Unavailable levels are disabled. A saved unavailable choice resets to Off with
an explicit Log message, keeping the settings window usable on another GPU.

This is geometry MSAA, not postprocess smoothing. Colour/depth surfaces render
with the selected sample count. Each surface also has a single-sample image,
resolved only after colour changes and before texture sampling or publication.
Feedback copies preserve the multisample colour data. Reflections/cubemaps,
readback, ordinary texture sampling and interpolation use resolved images.
Presentation resolves before binding the window's single-sample target.
The resource budget reserves multisample colour/depth, resolve and diagnostic
storage. Disabling MSAA releases its surfaces and transfer objects on reset.
No runtime HLSL compilation or gameplay readback is used.

A bounded native D3D11 probe verified 2/4/8 support in all four render formats
on RTX 5060 Ti and WARP. It also confirmed that ordinary partial copies while
growing multisample targets produce D3D11 validation errors. Growing MSAA targets
therefore uses built sample-frequency shaders to load and preserve each colour
and depth sample. Eight masked stencil passes preserve the full stencil byte
per sample. New regions are cleared; existing scene depth and masks stay intact.
Single-sample target growth retains its existing exact packed-depth transfer.

Native checks cover partial geometric coverage at all three levels, pixel-exact
fine texture detail, feedback, presentation, cubemap resolves, history resize,
resource release, RGBA8/D24S8 and RGB565/D16 growth, and per-sample depth/stencil
preservation against a scene rendered before growth. Stencil checks use 0xA5 to
exercise upper and lower bits. The geometry coverage fixture crosses the sample
positions; an exactly aligned diagonal can miss both 2x samples and legitimately
retain aliasing. 4x and 8x cover more edge orientations, at greater GPU cost.
The hidden window check also executes MSAA and transfer shaders from b2.exe's
build-time bytecode bank, before returning to the default mode.
