Confirmed correctness fixes
1. REP MOVS compared guest addresses when choosing overlap handling. Low,
80000000 and F0000000 views can alias the same RAM. Copy decisions now compare
resolved storage addresses, preserving x86 propagation through overlapping aliases.
The native REP MOVSB reference disagreed before and agrees after the fix for
1040 -> 80001041, eight bytes. Existing CPU checks cover all nine view pairs,
8/16/32-bit elements and both traversal directions.

2. Pending reads held host files but could lose their guest file/event objects
when handles closed. Requests now retain those objects through completion.
Waits also retain the owner of an embedded file dispatcher at +38h. Reference
ownership is acquired before issuing the native read and released on completion.
Existing storage checks close both handles early and verify payload, status,
signalling and final release.

3. The game draws into auxiliary framebuffers, then copies colour to main.
Temporal reconstruction previously used unrelated main-target depth and only
jittered/masked target zero. Depth, responsive masks and jitter now follow the
full-size drawing target actually handed to presentation. Existing DLSS, FSR and
XeSS diagnostics inspect the inputs delivered to each SDK.

4. DSP DO counts were always truncated to 16 bits. Normal DSP56300 mode uses
24 bits and zero skips; SR.SC compatibility mode uses 16 bits with zero meaning
65536 iterations. Generation now uses a mode-aware helper. All 67 effects checks
pass, with the work limit unchanged and no runtime instruction decoder.

5. Kernel performance queries exposed host QPC units. Xbox ACPI time uses
3375000 Hz; XAPI/RDTSC retains 733333333 Hz. Safe integer scaling now keeps those
clock domains separate. Original wrappers 288214/288226 were decoded and the
latter is exercised with one ACPI second, requiring 1000000 microseconds.
The old assertion about the undefined EAX return of void AvSendTVEncoderOption
was corrected to check its output buffer.

6. Ended threads retained fibers, stacks and dispatcher storage indefinitely.
Non-current ended fibers are now deleted; stacks are freed after pending I/O
completes. Handles, waits and explicit references retain dispatcher storage.
The current context remains available for diagnostics. The active-context limit
now counts running/waiting/suspended threads, rather than retained completed
metadata. The existing storage diagnostic runs 70 original XGetVideoFlags
workers on real fibers, retains 68 completed handles simultaneously, then closes
them and checks complete reclamation. No invented guest callback is used.

7. Rumble expired after an arbitrary second. Xbox motor state persists until
replaced. The binding now renews SDL's bounded effect every 30 seconds, honours
replacement/stop and clears removed devices. SDL caps each effect at 65535 ms.
Original XInputSetState at 28D1EC was decoded in a bounded 157-byte range; its
51-byte function submits a report without a duration argument. The existing
virtual-controller diagnostic checks persistence past a second and explicit stop.

8. Default floating context used x87 037F. Xbox kernel threads begin with 027F
(53-bit precision) and MXCSR 1F80. New threads and standalone original SDK calls
now use those defaults. Actual translated FNINIT still performs the ISA's 037F
reset. Original startup E682C, exception prologue 11FCD0, TLS dispatcher E6690
and D3D initialization 21A400 contain no direct floating-control reset. Kernel
context evidence comes from the pinned Cxbx implementation cited below.

backgrounds, using actual texture content rather than texture IDs or guessed
