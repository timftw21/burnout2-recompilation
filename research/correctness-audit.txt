Confirmed correctness fixes
1. REP MOVS compared guest addresses when choosing overlap handling. Low,
80000000 and F0000000 views can alias the same RAM. Copy decisions now compare
resolved storage addresses, preserving x86 propagation through overlapping aliases.
The native REP MOVSB reference disagreed before and agrees after the fix for
1040 -> 80001041, eight bytes. Existing CPU checks cover all nine view pairs,
8/16/32-bit elements and both traversal directions.

2. Pending reads held host files but could lose their guest file/event objects
when handles closed. Requests now retain those objects through completion.
Waits also retain the owner of an embedded file dispatcher at +38h. Reference
ownership is acquired before issuing the native read and released on completion.
Existing storage checks close both handles early and verify payload, status,
signalling and final release.

3. The game draws into auxiliary framebuffers, then copies colour to main.
Temporal reconstruction previously used unrelated main-target depth and only
jittered/masked target zero. Depth, responsive masks and jitter now follow the
full-size drawing target actually handed to presentation. Existing DLSS, FSR and
XeSS diagnostics inspect the inputs delivered to each SDK.

4. DSP DO counts were always truncated to 16 bits. Normal DSP56300 mode uses
24 bits and zero skips; SR.SC compatibility mode uses 16 bits with zero meaning
65536 iterations. Generation now uses a mode-aware helper. All 67 effects checks
pass, with the work limit unchanged and no runtime instruction decoder.

5. Kernel performance queries exposed host QPC units. Xbox ACPI time uses
3375000 Hz; XAPI/RDTSC retains 733333333 Hz. Safe integer scaling now keeps those
clock domains separate. Original wrappers 288214/288226 were decoded and the
latter is exercised with one ACPI second, requiring 1000000 microseconds.
The old assertion about the undefined EAX return of void AvSendTVEncoderOption
was corrected to check its output buffer.

6. Ended threads retained fibers, stacks and dispatcher storage indefinitely.
Non-current ended fibers are now deleted; stacks are freed after pending I/O
completes. Handles, waits and explicit references retain dispatcher storage.
The current context remains available for diagnostics. The active-context limit
now counts running/waiting/suspended threads, rather than retained completed
metadata. The existing storage diagnostic runs 70 original XGetVideoFlags
workers on real fibers, retains 68 completed handles simultaneously, then closes
them and checks complete reclamation. No invented guest callback is used.

7. Rumble expired after an arbitrary second. Xbox motor state persists until
replaced. The binding now renews SDL's bounded effect every 30 seconds, honours
replacement/stop and clears removed devices. SDL caps each effect at 65535 ms.
Original XInputSetState at 28D1EC was decoded in a bounded 157-byte range; its
51-byte function submits a report without a duration argument. The existing
virtual-controller diagnostic checks persistence past a second and explicit stop.

8. Default floating context used x87 037F. Xbox kernel threads begin with 027F
(53-bit precision) and MXCSR 1F80. New threads and standalone original SDK calls
now use those defaults. Actual translated FNINIT still performs the ISA's 037F
reset. Original startup E682C, exception prologue 11FCD0, TLS dispatcher E6690
and D3D initialization 21A400 contain no direct floating-control reset. Kernel
context evidence comes from the pinned Cxbx implementation cited below.

backgrounds, using actual texture content rather than texture IDs or guessed

Confirmed corrections
---------------------
1. NtQueryVirtualMemory scanned backward from the queried page and returned
   the beginning/size of the entire matching region. The contract starts at
   the requested page, rounds it down, and counts matching pages forward.
   Corrected the range; AllocationBase remains the owning reservation.

2. Virtual allocate/free/query used the physical allocator's alias folding.
   A high address could locate a low allocation, then index its page metadata
   with the original high address. Virtual operations now use an exact virtual
   lookup; physical Mm operations retain their verified alias behavior.

3. Decommit added the caller's size before checking its range. Unsigned wrap
   could produce a reversed iterator range. Check the remaining allocation
   capacity before adding/rounding or changing memory.

4. Portable x87 FCOMI/FUCOMI changed x87 C0/C2/C3 in addition to CPU flags.
   Intel specifies that these x87 condition bits are unaffected. Separate the
   two comparison destinations. The private native-vs-portable probe reproduced
   both wrong status results before the correction and passes afterward.

5. Portable MMX stores read an unused 64-bit operand from the destination,
   including MOVD's four-byte destination. Avoid loading operands for stores.
   The pre-change -O0 helper faults on a destination ending at a guarded page;
   the corrected helper completes. This is source-level ARM helper validation
   on x86-64; it does not establish Mac hardware behavior or a Release symptom.

6. The compiled DSP compatibility check verified instruction bytes but ignored
   the state/scratch descriptors and declared memory layout from which fixed
   coefficient addresses were generated. Reject incompatible layouts before
   initialization; mutable parameter data remains permitted. The original disc
   layout remains supported. Added two cases to the existing effects diagnostic.

7. An audio callback could continue after publishing failure and overwrite the
   error string while the game thread read it after the atomic failure flag.
   A failed callback now stays stopped, keeping the published error immutable.
   Normal mixing and its locking/queue ordering are unchanged.

8. POSIX settings loading retained Windows CR characters in paths, numbers and
   booleans. Accept CRLF explicitly. Save the complete configuration through
   the existing atomic file-publishing helper instead of truncating the live
   file before formatting/writing succeeds. Existing hidden-window diagnostics
   now cover CRLF input and preservation when publication fails.

All 104 tracked files in src were in scope. The worktree contained the same
104 source files. This review found 13 issues. The first two can destroy

Findings
--------

1. Windows Setup can overwrite or claim the player's original disc image.
   src/installer.cpp:330, uninstall at line 382. A first install accepts a
   folder containing data/local/game.iso. If the player selects that very file
   and leaves the default Copy setting enabled, Setup reuses it and writes its
   path into the uninstall manifest. Uninstall removes each listed file.
   Reproduced with the real setup executable, registration disabled, and a
   disposable XDVDFS image containing the verified original XBE. Setup passed
   and listed the pre-existing image. In a second first-install test, an
   existing destination and the selected source had different hashes and
   contained the same supported XBE. Setup overwrote the existing destination
   with the selected source. Both cases used disposable images. Require
   ownership before replacing an existing disc and record only a destination
   that Setup created or previously owned.

2. Append-only writes can overwrite existing data on Linux and macOS.
   src/host_posix.cpp:149 and 268, called from src/xbox.cpp:2686 and 3107.
   FILE_APPEND_DATA opens an ordinary writable descriptor. The write uses
   the current or supplied offset. In a current-source Linux probe, opening a
   file containing ABC with append-only access and writing Z at offset zero
   produced ZBC. The same open, seek and write on Windows produced ABCZ,
   as the local-file contract requires. Preserve append
   semantics for both synchronous and asynchronous writes, including concurrent
   writers. Microsoft documents the access right here.
   https://learn.microsoft.com/en-us/windows/win32/fileio/file-access-rights-constants

3. A failed first installation leaves a folder that Setup refuses to repair.
   src/installer.cpp:346 and 277. Setup publishes the executable and libraries
   before the game files and ownership manifest. Holding a disposable
   data/local/default.xbe open during installation produced Windows error 5.
   The executable and libraries were present, and install-manifest.txt was
   absent. After the handle closed, a second install rejected the folder as
   nonempty. Record and roll back the files published by a failed attempt, or
   retain enough verified transaction state to resume it. Checking the initial
   file locks alone leaves the same failure possible during publication.

4. Preparing game files can silently erase preferences.
   src/installation.cpp:116. The migration checks the size of settings.cfg
   and treats an unsuccessful read like an empty file. In an isolated Windows
   installation, the existing file permitted replacement and denied reading
   its contents. --prepare-game-files exited successfully. The output retained
   the XBE and disc paths and lost both existing preferences. A separate
   sharing violation that also prevented replacement produced a visible error
   and kept the preferences. Check that the input opens and reaches EOF
   successfully before publishing any replacement.

5. POSIX delete-on-close breaks file sharing and makes a name reusable early.
   src/host_posix.cpp:141 and 181. In a Linux probe with two open handles,
   closing the delete-on-close handle unlinked the file while the reader was
   still open. Creating a new file with the same name then succeeded. The
   equivalent Windows control rejected creation with error 5. Linux also
   accepted a delete-on-close open while an existing reader denied delete
   sharing. Include the flag in the delete-access check and maintain pending
   deletion across all handles for the file identity until final close.
   https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew

6. Save directory listings discard file timestamps on every host.
   src/xbox.cpp:3144 and 3166. NtQueryDirectoryFile class 1 collects only the
   name, size and directory bit. It clears the output and leaves the creation,
   access and write times at zero. For the same writable file, the handle
   query at line 2959 reads those times from the host. A caller enumerating
   saves and a caller opening each save can therefore see different dates.
   The XBE imports both services at 0x00293D40 and 0x00293D00. Carry the
   available times into the Xbox directory record. The Xbox layout uses an
   eight-byte prefix before the first timestamp.
   https://github.com/XboxDev/nxdk/blob/master/lib/xboxkrnl/xboxkrnl.h#L315

7. A successful read-only attribute change disappears from guest queries.
   src/xbox.cpp:2935, 2964, 2983 and 3172. The set-information service at
   line 3229 passes FileAttributes to the host. Both the basic/network-open
   handle queries and directory listings rebuild the flags from file versus
   directory and writable volume versus disc. They omit a writable-volume
   file's recorded read-only bit. The path-based query at line 3279 returns
   the host attributes. A guest can therefore set the bit, then get different
   answers by handle and by name. Derive the guest flags from current host
   metadata in the query paths.
   https://github.com/XboxDev/nxdk/blob/master/lib/xboxkrnl/xboxkrnl.h#L361

8. The portable x87 implementation loses the denormal-operand status bit.
   src/portable_floating.h:50 and 102. It maps SoftFloat's five exception
   flags and converts single/double inputs before recording their original
   representation. With the smallest positive single as input, native x87
   FLD returned status 0x3802 and the portable helper returned 0x3800.
   FLD1 followed by FADD returned 0x3822 versus 0x3820. Both comparisons ran
   on the same x86-64 CPU against current portable code. The verified title
   uses FLD m32 at 0x0001EF10 (D944240C). Detect denormal operands before
   conversion and apply the guest mask/status rules. This backend ships on
   Apple Silicon. A game frame depending on this flag has not been identified.
   https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html
   https://github.com/ucb-bar/berkeley-softfloat-3/blob/master/doc/SoftFloat.html

9. Portable FNINIT erases the data shared by the x87 and MMX registers.
   src/portable_floating.h:19 and 96. fp_reset clears the full saved register
   image. The instruction resets the x87 environment and marks the registers
   empty while preserving the physical register contents. Loading MM0 with
   0x1122334455667788, executing FNINIT and storing MM0 returned that value
   on hardware and zero through the portable helper. Preserve the physical
   register data when implementing the instruction. The FNSAVE reset at
   line 92 uses the same helper.
   https://www.intel.com/content/dam/www/public/us/en/documents/manuals/64-ia-32-architectures-software-developer-vol-2a-manual.pdf

10. A programmed texture border is sampled as transparent black.
    src/gpu.cpp:343, src/render.cpp:226 and 1856. Border address mode is
    supported, but the draw state omits NV097_SET_TEXTURE_BORDER_COLOR
    (0x1B24 plus 0x40 per stage). The sampler cache key omits it too, and
    D3D11 receives a zero-initialized BorderColor. Two otherwise identical
    register-color samplers asking for different borders therefore share
    the same black border. Carry the color through the draw state, sampler
    key and D3D11 descriptor. The sources below establish the register and
    how the destination sampler uses it. No frame-specific impact was measured.
    https://github.com/XboxDev/nxdk/blob/master/lib/pbkit/nv_regs.h#L624
    https://github.com/xemu-project/xemu/blob/master/hw/xbox/nv2a/pgraph/gl/texture.c#L178
    https://learn.microsoft.com/en-us/windows/win32/api/d3d11/ns-d3d11-d3d11_sampler_desc

11. Wi-Fi can be reported to the title as a connected Ethernet cable.
    src/host_posix.cpp:420 and 425. macOS accepts any running, non-loopback
    link-layer interface and returns only the active bit, even for wired
    Ethernet with known speed. Linux accepts a physical device with Ethernet
    framing and carrier. Managed mac80211 Wi-Fi devices can meet all three
    conditions. This conflicts with research/native-ethernet.txt. The original
    title calls PhyGetLinkState at 0x000E7295 and masks bit 0 at 0x000E72A7.
    Identify the physical medium, link state and negotiated speed separately.
    The platform implementations establish the classification error. Physical
    connections were not changed during this audit.
    https://github.com/apple-oss-distributions/configd/blob/main/SystemConfiguration.fproj/SCNetworkConfiguration.h
    https://github.com/torvalds/linux/blob/master/net/mac80211/iface.c
    https://github.com/torvalds/linux/blob/master/net/ethernet/eth.c

12. Batch totals count replaced platform routines as translated CPU code.
    src/batch.cpp:114, 207 and 296. A one-entry batch for D3DDevice_IsBusy
    at 0x00216870 reported one compiled, closed function and 13 compiled
    instructions. Its generated body calls native_platform. Across the release
    report, 72 such entries account for 2,213 decoded instructions within
    the headline 713,245. The per-function native_platform_api field makes
    this recoverable. Publish separate counts for translated bodies and
    platform bindings while retaining an aggregate for callable entries.
    DESIGN.txt requires this distinction. It affects coverage reporting.

13. The POSIX crash handler calls a formatter without a signal-safety guarantee.
    src/diagnostics_posix.cpp:52. The fatal signal can interrupt libc, then
    call snprintf from the handler. Re-entering a libc operation in that
    state can prevent both log completion and the intended re-raise. The
    later write already uses an async-signal-safe primitive. Format the
    numbers and fixed text using bounded local operations as well. This is
    a source-level portability finding. The audit did not induce a crash.
    https://man7.org/linux/man-pages/man7/signal-safety.7.html

Fixes and verification, 2026-11-24
==================================

The numbered results below correspond to the 13 findings above. The rebuilt
Windows Setup used a prebuilt application payload and ran 31 checks with
registration disabled in disposable directories. Its small XDVDFS fixture
contained the exact default.xbe from the supported US disc. The settings check
also prepared game files directly from the original 3,074,031,616-byte XISO.

1. Setup records the identity of a disc it copied. Installing from the image
   already in the destination and uninstalling preserved its SHA-256. A
   different existing image survived a refused install. An owned copy was
   removed, while a replacement with identical bytes and a disc claimed by
   an ambiguous V1 manifest both survived uninstall.
2. POSIX append-only handles append through one O_APPEND descriptor per
   open file identity. A synchronous write and an asynchronous write with
   offset zero turned ABC into ABCZY. Two concurrent writers using both
   APIs added all 200 bytes on ext4 and a WSL-mounted NTFS volume. Ordinary
   write access still overwrote the requested offset. The synchronous append
   position matched Win32. Apple's AIO write path honors O_APPEND when it
   chooses whether to apply the supplied offset.
   https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/kern_aio.c#L2069
3. Setup journals publication and restores displaced files on failure. A
   locked XBE rolled back a first install, and retry succeeded. A locked
   upgrade restored the previous executable and manifest hashes. Fixtures
   for interruption during first install and upgrade verified recovery by
   both Setup and Uninstall. Setup also repaired an older, unjournaled
   partial installation after verifying its payload hashes. An unrelated
   executable and a user folder with a staging-like name were preserved.
4. With a Windows ACL denying ReadData but allowing replacement,
   --prepare-game-files failed and preserved both settings and the old XBE.
   Restoring read access migrated both preferences and extracted the
   supported XBE with SHA-256 B5207C40C11D7C5B5E129EF555F7632FA3584A4240BD0421C2B1B9AD9BFED7BF.
5. Delete-on-close now requires delete sharing and reserves the name until
   the final handle closes. POSIX checks covered two handles on different
   hard links, a denied new open, a denied recreation, final deletion of
   the selected link and cancellation of a separate delete disposition.
6. The writable directory service now returns creation, access and write
   times. The storage diagnostic set three distinct timestamps and compared
   all four fields by name, by handle and by directory entry. All three
   queries use the existing last-write value for the change-time field.
7. The same diagnostic set and cleared the read-only bit through the guest
   kernel. Basic and network-open handle queries, the name query and the
   directory listing agreed on the attributes after both changes.
8. The portable backend recognizes denormal input before conversion and
   preserves x87 exception priority, stack effects and pending delivery.
   Hardware comparisons covered both signs, four rounding modes, masked and
   unmasked operands, single/double/extended loads, arithmetic and compares.
9. FNINIT and the FNSAVE reset now preserve the eight physical registers
   when TOP changes. Checks of register bytes, tags and the MM0 value
   0x1122334455667788 passed. Together, findings 8 and 9 were exercised by
   256 x86 hardware comparisons plus the MM0 check on each of two builds,
   native x86-64 portable code and AArch64 portable code executed with QEMU.
   https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html
10. NV097 register-sourced texture border colors reach the Windows D3D11
    sampler and its cache key. DXMT exposes only transparent black, opaque
    black and opaque white. The portable renderer reconstructs other RGBA
    borders from black-border and white-border samples with the same filter

    distinct borders, including reuse of the first color. A separate edge
    sample checks a half-texel blend in all four channels. Texture-sourced

    https://github.com/XboxDev/nxdk/blob/master/lib/pbkit/nv_regs.h
    https://github.com/3Shain/dxmt/blob/9839e55f98d4aca103957ee4132d6395a325a9ed/src/d3d11/d3d11_state_object.cpp#L701

    https://github.com/apple-oss-distributions/xnu/blob/main/bsd/net/if_media.h
